Integrate real AI-powered diary generation that writes professional construction site diary text based directly on uploaded photos, combined with optional supervisor notes.

TECH STACK ASSUMPTIONS:
- Flutter frontend
- OpenAI vision-capable model (GPT-4o or GPT-4.1)
- Photos are already captured and available as image files or image URLs
- Backend logic can be local for now

GOAL:
When a user uploads construction site photos, the AI must generate a realistic, professional daily site diary based on what is visibly observable in those photos, using cautious, defensible language.

--------------------------------------------------
SYSTEM PROMPT (FIXED – MUST MATCH EXACTLY)
--------------------------------------------------
"You are a construction site supervisor preparing a professional daily site diary.

Describe only what is clearly visible in the provided photos.
Do not assume measurements, dimensions, compliance, or safety outcomes.
Use cautious observational language such as 'appears', 'observed', 'visible', or 'consistent with'.

Do not invent details that cannot be visually confirmed.
Do not guarantee site safety, correctness, or regulatory compliance.

Write in a neutral, professional tone suitable for construction records in Australia and New Zealand."

--------------------------------------------------
USER PROMPT (DYNAMIC – GENERATED BY THE APP)
--------------------------------------------------
"Create a daily site diary based on the uploaded site photos and the information below.

Site Name: {{site_name}}
Site Address: {{site_address}}
Date: {{date}}

Supervisor Notes (if provided):
{{notes}}

Instructions:
- Describe observable site conditions from the photos
- Describe visible excavation, structures, coverings, barriers, fencing, and signage
- Mention safety-related observations only if they are clearly visible in the photos
- Do not assume excavation dimensions, structural correctness, or compliance
- If visibility is limited, clearly state that observations are based only on photographed areas
- Include a short 'Health & Safety Observations' section based solely on visible conditions

Important:
This output is a draft site diary. The user must review and edit before approval."

--------------------------------------------------
PHOTO HANDLING REQUIREMENTS
--------------------------------------------------
- Send up to 3 representative photos per diary generation
- Order photos logically (overview first, then details)
- If no photos are available, generate diary text using supervisor notes only
- Do NOT attempt OCR or quote text unless it is clearly legible

--------------------------------------------------
OUTPUT REQUIREMENTS
--------------------------------------------------
- Return a single structured diary entry
- Use clear paragraphs (not heavy bullet points)
- Include:
  - General site observations
  - Work progress observations (if visible)
  - Health & Safety Observations section
- Prepend the diary with:
  "Draft – User review required"

--------------------------------------------------
SAFETY & LEGAL CONTROLS
--------------------------------------------------
- Never state that a site is compliant, safe, or correct
- Never state that work meets plans or dimensions
- Never auto-save AI output
- Store only the user-approved version

--------------------------------------------------
ERROR HANDLING
--------------------------------------------------
- If the AI request fails, show:
  'Diary generation unavailable. Please try again.'
- The app must not crash if AI is unavailable

--------------------------------------------------
SCOPE LIMITS (DO NOT BUILD YET)
--------------------------------------------------
- No compliance scoring
- No measurements or dimension validation
- No incident reporting
- No legal language
- No role-based permissions

END GOAL:
Produce a defensible, professional construction site diary that reflects observable conditions from uploaded photos, suitable for PDF export and management review.
